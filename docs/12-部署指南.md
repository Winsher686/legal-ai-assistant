# 部署指南

本文档说明如何将项目部署到服务器，实现「租到服务器后无需改代码即可完整运行」。

## 一、服务器环境要求

- 操作系统：Ubuntu 22.04（或其他 Linux）
- 硬件：建议 ≥ 8GB 内存（Milvus / Neo4j / PG 同时运行）
- 已安装：Docker + Docker Compose

```bash
# 安装 Docker
curl -fsSL https://get.docker.com | sh

# 安装 Docker Compose 插件
sudo apt-get install -y docker-compose-plugin
```

## 二、部署步骤

### 1. 拉取代码

```bash
git clone <你的仓库地址> legal-ai-assistant
cd legal-ai-assistant
```

### 2. 配置环境变量

```bash
cp .env.example .env
vim .env
```

**必填项**（其余用默认值即可）：

```bash
# LLM（三选一，二选一填写 provider）
LLM_PROVIDER=deepseek          # openai / deepseek / qwen
LLM_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat

# 生产环境关闭 mock
USE_MOCK=false

# 安全密钥（务必修改）
SECRET_KEY=生成一个随机字符串
```

### 3. 启动服务

```bash
docker compose up -d --build
```

首次启动会自动拉取镜像、构建后端、初始化数据库表。

### 4. 验证

```bash
# 查看服务状态
docker compose ps

# 健康检查
curl http://localhost/health

# 查看后端日志
docker compose logs -f backend
```

## 三、初始化数据

数据库表会在后端启动时自动创建（`init_db.py`），默认账号：

| 用户名 | 密码 | 角色 |
| ------ | ---- | ---- |
| admin | admin123 | 管理员 |
| legal | legal123 | 法务 |
| employee | emp123 | 员工 |

## 四、上传知识文档并测试问答

```bash
# 1. 登录获取 token
curl -X POST http://localhost/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"legal","password":"legal123"}'

# 2. 上传文档（复制返回的 access_token）
curl -X POST http://localhost/api/document/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@knowledge_base/sample/合同管理制度.md" \
  -F "document_type=company_policy" \
  -F "version=V3.0"

# 3. 问答
curl -X POST http://localhost/api/chat/query \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"question":"采购合同超过500万元需要法务审核吗？"}'
```

## 五、常见问题

### Q1: Milvus 启动失败？

Milvus 依赖 etcd 和 minio，确保三者都正常：

```bash
docker compose logs milvus
docker compose logs etcd
docker compose logs minio
```

### Q2: LLM 调用报错？

检查 `.env` 中 `LLM_API_KEY` 和 `LLM_BASE_URL` 是否正确，且服务器能访问外网。

### Q3: 想先验证再连 LLM？

临时设置 `.env` 中 `USE_MOCK=true`，会使用内存向量库 + 假 LLM，端到端跑通逻辑后再切回真实配置。

## 六、停止与清理

```bash
# 停止（保留数据）
docker compose down

# 停止并删除数据卷（慎用）
docker compose down -v
```
